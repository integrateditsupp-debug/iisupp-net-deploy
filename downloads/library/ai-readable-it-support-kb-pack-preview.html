Sample article pattern

What one AI-readable support article looks like

This is a representative slice. The full pack expands this into repeatable article templates, routing fields, escalation logic, and reusable support-taxonomy patterns.

Issue frame

Capture the symptom in user language, the systems involved, what changed recently, and whether the impact is local, team-wide, or business-critical.

Safe-first flow

Separate user-safe checks from admin-only work so the next person does not guess which actions are acceptable at each level.

Escalation truth

Define the exact point where the issue becomes a security risk, multi-user outage, or privileged task that should stop self-service.

{
  "article_id": "m365-outlook-sync-001",
  "title": "Outlook desktop not syncing after password change",
  "audience": ["end_user", "technician"],
  "signals": ["password changed recently", "desktop app stale", "webmail still works"],
  "safe_first_checks": [
    "Confirm webmail works",
    "Check account status in Outlook",
    "Prompt for recent credential change"
  ],
  "admin_boundary": [
    "Profile reset",
    "Token cleanup",
    "Mailbox or conditional-access review"
  ],
  "escalate_when": [
    "multiple users affected",
    "security or lockout signal appears",
    "admin-only fix required"
  ]
}
The goal is not to pretend every issue can be automated. The goal is to make the support article trustworthy enough that humans and later AI systems start from the same clean operating truth.
