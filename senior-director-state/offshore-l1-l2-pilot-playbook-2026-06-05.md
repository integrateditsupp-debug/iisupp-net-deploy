# Offshore L1/L2 Support Pilot Playbook

Created: 2026-06-05

Owner: offshore-support-strategy-agent

Status: completed draft. Do not hire, contact contractors, or promise offshore delivery to clients until Ahmad approves.

## Purpose

Create a controlled way for IIS to add support capacity without pretending to be a large MSP. IIS remains senior-led and accountable. Offshore resources support defined low-risk tasks under clear quality, access, confidentiality, and escalation controls.

## Pilot Offer

Name: IIS Remote Support Assist Pilot

Target buyer:
- Small MSPs needing overflow.
- SMBs needing basic after-hours support.
- Companies with repeated L1/L2 tickets.

Pilot duration:
- 30 to 60 days.

Draft price:
- CAD/USD 3,000 to 10,000 per month depending on ticket volume, hours, and scope.

Initial scope:
- Password reset guidance where client-approved process exists.
- M365/Outlook/Teams/OneDrive basic troubleshooting.
- Printer, Wi-Fi, VPN, audio/video, browser, and Windows/Mac L1 triage.
- Ticket intake, categorization, documentation, and escalation.
- Knowledge base updates.
- Monthly report draft.

Excluded until approved:
- Admin credential ownership.
- Security incident response.
- Firewall/network production changes.
- Privileged identity changes.
- Data deletion or mailbox export.
- Client financial/legal/HR systems.
- Any action requiring unrestricted client admin rights.

## Roles

### IIS Accountable Lead

Usually Ahmad.

Responsibilities:
- Client relationship.
- Scope control.
- Quality gate.
- Escalations.
- Technical governance.
- Monthly report review.

### Offshore L1 Analyst

Responsibilities:
- Intake.
- Basic troubleshooting.
- Knowledge-base guided resolution.
- Ticket notes.
- Escalation when outside runbook.

Must have:
- Clear written English.
- Basic Microsoft 365 support experience.
- Windows/Mac troubleshooting.
- Ticket documentation discipline.

### Offshore L2 Analyst

Responsibilities:
- Deeper M365/endpoint troubleshooting.
- Runbook improvement.
- Escalation package preparation.
- QA assist.

Must have:
- M365 admin/support familiarity.
- Endpoint, networking, VPN, Teams/Outlook/OneDrive experience.
- Security awareness.

### QA Reviewer

May be Ahmad initially.

Responsibilities:
- Sample tickets.
- Check notes, tone, resolution quality, and escalation correctness.
- Track repeat issues and training needs.

## Access Model

Preferred starting model:
- Client tool access by named account.
- Least privilege.
- MFA required.
- No shared passwords.
- No admin access unless explicitly approved.
- Session notes required.
- Offboarding checklist for every resource.

Tools:
- Client-approved ticketing system.
- Client-approved remote support tool.
- Microsoft 365 admin access only if scoped and approved.
- IIS internal KB/runbook library.

## Confidentiality Controls

Required before any client work:
- NDA or subcontractor confidentiality agreement.
- Client data handling policy.
- No local downloads unless approved.
- No screenshots outside ticketing system unless approved.
- No use of client data in AI tools without written approval.
- Immediate access removal at end of assignment.

## QA Model

Minimum QA:
- 20% ticket sample in first 30 days.
- 10% ticket sample after quality stabilizes.
- 100% review for escalated or sensitive tickets.

QA checks:
- Correct category.
- Clear notes.
- User-friendly response.
- No unsupported promises.
- No privilege overreach.
- Correct escalation.
- Knowledge-base article linked or updated.

Quality metrics:
- First response time.
- Resolution time.
- Reopen rate.
- Escalation quality.
- User satisfaction where available.
- Repeat issue count.

## Escalation Matrix

Escalate to Ahmad/IIS immediately for:
- Security incident.
- Data loss.
- Executive/VIP issue.
- Legal/HR/finance system.
- Privileged account issue.
- Firewall/server/network outage.
- Unknown admin change.
- User complaint or reputational risk.

Escalation package must include:
- User.
- System.
- Symptoms.
- Steps already taken.
- Error messages.
- Screenshots if client-approved.
- Business impact.
- Recommended next action.

## Contractor Vetting Checklist

Before assigning work:
- Resume reviewed.
- Identity verified.
- References or prior work reviewed.
- Skills interview completed.
- Writing sample reviewed.
- Security awareness confirmed.
- NDA/confidentiality agreement signed.
- Time zone and availability confirmed.
- Tool access tested.
- Trial ticket exercise completed.

## Pilot Launch Checklist

1. Define client scope and exclusions.
2. Approve support hours.
3. Approve ticket categories.
4. Approve access model.
5. Assign L1/L2 resource.
6. Train on client environment.
7. Load runbooks.
8. Start with supervised tickets.
9. Review first 10 tickets.
10. Send weekly quality report.

## Pricing Assumptions

Basic pilot:
- Up to 25 tickets/month.
- Business-hours overflow.
- CAD/USD 3,000 to 4,500 monthly.

Standard pilot:
- Up to 75 tickets/month.
- L1 plus limited L2.
- CAD/USD 5,000 to 7,500 monthly.

High-touch pilot:
- Up to 150 tickets/month.
- L1/L2 plus weekly reporting.
- CAD/USD 8,000 to 10,000 monthly.

Change control:
- Extra ticket volume billed separately.
- After-hours or weekend coverage priced separately.
- Onsite work excluded unless partner-backed.

## Client-Facing Positioning

Use:

Integrated IT Support uses a senior-led delivery model supported by controlled specialist capacity when needed. IIS remains accountable for scope, quality, escalation, and client communication. Additional support resources are assigned only after role fit, confidentiality, access, and quality controls are in place.

Avoid:

- "We have a large global team" unless proven.
- "24/7 support" unless staffed and contracted.
- "Security operations" unless partner-backed.
- "Unlimited tickets" without strict limits.
