# RUN-L — REPEATABLE REVENUE (CC executable, branch `cc/run-l-*`)
**Prereq:** RUN-K built + verified + merged (met 2026-07-21). **Read first:** `VISION-AND-GOAL-STANDING.md` (REVENUE MANDATE, free-only HARD LAW, Rule 14 honesty, Rule 15 preserve-everything), then the K assets (`payment-receipt-ledger.mjs`, `time-to-first-dollar.mjs`, `one-page-ask.mjs`) and the J assets.
**Rules:** Rule 14 real-or-empty — never a fabricated customer, payment, minute, price, or date. Free only. **No external send / signing / payment / charge / account creation / deploy — every one staged to Ahmad's one click.** Additive only (Rule 15).

## L1 — DEMAND-TO-ASK CONVEYOR (buildable, free)
1. One pass that takes every real demand-intake record (G1) and reports exactly where it is on the K-chain — engagement, evidence, packet, handoff, ask, payment — and the ONE next real step for each. A record with no real artifact behind it is reported as *not started*, never as *in progress*.
2. The conveyor produces staged actions only. It must be structurally incapable of sending anything (static-scan locked, as in H3/K3), and a stage may only advance on the existence of a real artifact — never on elapsed time and never on optimism.
**Exit L1:** not-started / mid-chain / ask-ready / paid all reachable from fixtures; every stage advance traces to a real artifact id; nothing sends; test-locked; full suite green.

## L2 — SECOND-CUSTOMER REPEATABILITY (buildable, free)
1. Prove the chain runs end-to-end for a SECOND real account with zero bespoke code and zero hand-derived values — same modules, different records, honest output both times.
2. Report what had to be entered by hand for each account. If a step still needs a human to re-derive something, name it as a repeatability gap instead of quietly absorbing it.
**Exit L2:** two independent fixture accounts both produce correct, different, honest outputs; the hand-entry list is real and complete; a deliberately broken second account fails honestly rather than inheriting the first account's data; test-locked; full suite green.

## L3 — HONEST PRICING FLOOR (buildable, free)
1. From J2 observed minutes and K1 verified receipts only: what an account actually costs us to deliver per month, and therefore the floor below which a quote loses money. No modelled rate, no assumed utilisation.
2. Without a recorded operator cost basis the answer is **"cannot be stated"** — never a comfortable default. A quote at or below the floor is flagged before it can reach a K3 page.
**Exit L3:** floor-known / floor-unknown / quote-below-floor all reachable; every input traces to a real record; the K3 ask refuses (or flags, per design) a below-floor price; test-locked; full suite green.

## HARD-STOPS (Ahmad one-click, never a hold, never faked)
Any outreach send · signing · invoicing/payment/Stripe charge · account creation · public deploy/publish · loan or purchase. Stage each to one click and keep building everything else. Cost is never a blocker (free-only).

## REPORT BACK
Branch, assets, staged one-click list, real-or-empty proof. Cowork re-verifies honesty (Rule 14) + preservation (Rule 15), runs the full suite, merges green+sane slices as sole .git writer, logs program status, and auto-releases RUN-M when L's exit criteria hold. Never idle.
