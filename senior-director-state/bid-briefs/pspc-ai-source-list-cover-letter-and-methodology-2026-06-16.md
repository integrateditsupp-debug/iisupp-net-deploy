### 6.1 Engagement Lifecycle

IIS runs every Government of Canada AI engagement through four phases. Each phase has defined entry criteria, deliverables, and exit gates. We do not move to the next phase without explicit client sign-off on the previous phase's exit gate.

**Phase 1 — Outcome Definition + Risk Triage** *(typical duration: 1–2 weeks)*

- Discovery workshop with client sponsor and operating stakeholders.
- Define the business outcome in measurable terms before any model selection.
- Apply Algorithmic Impact Assessment (AIA) screening per the Government of Canada Directive on Automated Decision-Making.
- Decide the category of automated decision-making in scope (Level I–IV per AIA).
- If any Level III or IV decision is in scope, IIS recommends additional governance review and a separate AIA filing before continuing.
- **Exit gate:** signed engagement charter with measurable outcome, AIA level documented, governance review path documented if applicable.

**Phase 2 — Narrow Pilot** *(typical duration: 4–8 weeks)*

- One workflow, one user group, measurable outcome, documented controls.
- Built on the client's existing data and tooling — IIS does not require platform replacement to pilot.
- Pilot population sized to allow statistically meaningful comparison against current-state baseline.
- All outputs logged with decision-capture metadata: timestamp, decider (human), options considered, rationale, confidence band.
- Weekly pilot review with client sponsor.
- **Exit gate:** measured pilot result vs. baseline; user-acceptance signed; controls reviewed against AIA documentation; go/no-go decision for Phase 3.

**Phase 3 — Governance Documentation** *(typical duration: 2–4 weeks; runs in parallel with Phase 4 start)*

- Human-oversight specification: who approves what, escalation paths, refusal rights.
- Data minimization specification per Privacy Act and applicable Treasury Board policy.
- Audit-trail specification with retention period and accessibility for evaluator review.
- Output-quality monitoring specification: drift thresholds, retraining triggers (if applicable), incident classification.
- AIA-aligned documentation: outputs, justification, decision categorization.
- Accessibility compliance per Government of Canada Web Standards (WCAG 2.1 AA minimum, IIS targets AA+ where feasible).
- **Exit gate:** governance package signed by client sponsor + IIS Engagement Lead; client compliance team confirms package supports their internal AIA review.

**Phase 4 — Operate + Measure + Tune** *(ongoing per engagement scope)*

- Monthly output review: outputs sampled, drift checked, user feedback synthesized.
- Quarterly governance review with client sponsor: AIA category re-validated, scope creep audited, controls re-tested.
- Incident-response procedure: defined severity levels, named escalation contacts, communication template.
- Documented retirement criteria: conditions under which the AI capability is decommissioned or escalated to a larger procurement.
- **Exit gate per quarter:** governance review signed; next-quarter scope confirmed; budget-actual variance reviewed.

### 6.2 Tooling and Vendor Posture

IIS's standing tooling posture for Government of Canada engagements:

- **Primary LLM family:** Anthropic Claude (Sonnet / Opus / Haiku family). IIS discloses the model family used per engagement and supports client-driven vendor change-control.
- **Orchestration framework:** Model Context Protocol (MCP) — open standard, vendor-portable. IIS implementations are not locked to a single LLM vendor.
- **Storage:** client-controlled. IIS does not retain client data outside the engagement workspace without explicit written authorization.
- **Hosting posture:** Canadian-region cloud where feasible (Microsoft Azure Canada Central / Canada East; AWS Canada Central). For LLM inference, IIS supports Anthropic's data-residency posture per Anthropic's published practices.
- **Subcontract bench:** vetted Canadian specialists for senior prompt engineering, AI governance review, technical writing, accessibility audit, and applied data science. Named under NDA at evaluator request.

### 6.3 Human Oversight Specification (worked example)

For every action-taking step, IIS's standing oversight pattern:

1. **AI proposes** — output produced with confidence band, rationale, alternatives considered.
2. **Human reviews** — named role (per engagement charter) reviews against acceptance criteria.
3. **Human decides** — accept, modify, refuse. Decision logged.
4. **Action executes** *(only after human decision)* — system performs the action with audit metadata.
5. **Outcome captured** — post-action result logged against the proposed output for governance review.

This pattern is built into ARIA's own operating posture today. Cowork agents draft; humans (or higher-trust agents under explicit gate) approve. The federal application is the same pattern with formal governance attached.

### 6.4 What IIS Does Not Do

For procurement clarity:

- IIS does not deliver autonomous AI that makes consequential decisions without human review.
- IIS does not claim model performance benchmarks IIS cannot reproduce in client environments.
- IIS does not use client data for model training under any circumstance without explicit written authorization.
- IIS does not deliver on-site work as standard posture — Band 1 engagements are remote-first.
- IIS does not currently hold ISO 27001, SOC 2, or equivalent third-party certifications. IIS positions on documented operating discipline, small-firm controls, and federal-procurement-grade decision-capture.
- IIS does not currently hold personnel security clearance. Engagements requiring Reliability or Secret clearance fall outside Band 1 scope and IIS will not bid them until clearance is in place.

### 6.5 Engagement Termination + Knowledge Transfer

IIS's standing posture on engagement close:

- All client-facing artifacts (decision logs, governance documentation, methodology assets) delivered in client-owned formats.
- All IIS-side workspace data securely deleted within 30 days of engagement close per a delivered certificate of destruction, unless the engagement charter authorizes longer retention.
- Knowledge transfer session with client team to ensure ongoing operation does not require IIS dependency for routine activity.
