## What moved the needle

1. **Token-overlap matcher** (`scoreRecipe`, Slice A) — the old matcher was substring-only, so filler words
   broke matches ("the internet **is** down" missed `internet down`). A keyword now scores when all its
   significant tokens appear anywhere in the query.
2. **Recipe synonyms** — added natural phrasings to `wifi-no-internet-v1`, `input-touchpad-disabled-v1`,
   `storage-eject-fail-v1`, and the new `office-file-repair-v1` so the *correct* recipe wins (no more
   title-token mis-matches to PDF/Bluetooth/Print-queue).
3. **KB-index fixes** — the baseline's 11 FAILs were mostly existing articles **not represented in
   `index-by-keyword.json`**. Indexed the real articles + synonym keys (password reset → `l1-password-001`,
   BYOD → `l2-byod-001`, deleted file → `l1-onedrive-002`, account lockout → `l2-active-directory-001`,
   overheating → `l2-performance-001`, start menu → `l1-windows-006`, webcam → `l1-webcam-001`, etc.).
4. **3 genuinely-missing articles authored** to close real gaps the baseline flagged: `l1-security-001`
   (lost/stolen device), `l1-mobile-email-001` (work email on a phone), `l1-newdevice-001` (new-device
   first-boot). Plus the passkey articles from Slice 1 cover passkey sign-in.

## Honesty note

The harness is the same model the baseline used (recipe-first, KB-keyword fallback). 100% PASS means every
call resolves to a relevant recipe (score ≥ 8) **or** a covering KB article — it does not assert the *fix
itself* runs (that is DoD criterion 1, verified separately on a live machine). Re-run the harness after any
matcher/index change to guard against regression.
