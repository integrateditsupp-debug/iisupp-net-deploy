## How it works

1. **Watches** — runs resident on the machine, scanning for the issues that actually generate tickets (printer/queue, network/DNS, Office won't open, disk, drivers, Windows Update, crashes and BSODs, browser, performance). Monitoring is content-blind: it never reads documents, screens or files.
2. **Diagnoses** — answers from a **280-article knowledge base first, at $0**, instantly; falls through to the ARIA cloud brain only for novel questions, then to an offline brain if there is no connection. The user always gets an answer.
3. **Fixes — under the person's control.** Applying fixes is off until the person turns it on. Then three modes:
   - **Manual** — ARIA explains the fix; the user runs it.
   - **Confirmed** — ARIA asks you once per fix: a one-click card, and it fixes it with you present after you say yes. It never fixes anything on its own (a fix you start yourself shows a 10-second cancel window; Ctrl+Alt+K stops everything).
   - **Autonomous** — ARIA tells you three times, then fixes safe things itself (after a 10-second countdown you can cancel); anything risky, and any step that needs administrator rights, goes to your IT contact and waits for a yes (a Windows UAC prompt — nothing runs unattended as administrator in 0.2.1).
4. **Hands off from the web** — a user on iisupp.net/aria clicks **"Resolve it for me" → "Open with ARIA Sentinel"** and the desktop app turns it into an approval request, then runs it through the same gates.
5. **Approve from anywhere** — a fix that needs a yes shows up in the app, as a desktop notification and (when email is on) as an email with one-time Approve / Deny links.

## Why IT and security teams trust it

- **Restore point before a medium-risk fix** where Windows allows one; otherwise the fix is held in preview and the app says why. Rollback is guided (System Restore), not silent.
- **Ctrl+Alt+K panic kill-switch** — stops everything at once: running actions, countdowns, pending approvals (no emailed link can run one afterwards), the watchers — and it stays stopped across a restart until someone presses Start ARIA. (An administrator step already running under its UAC prompt finishes its own command; nothing after it runs.)
- **Every action is audited** — a tamper-evident, hash-chained log of what ARIA did and why, exportable.
- **Compliance evidence pack** — SOC 2 / PIPEDA / GDPR / CCPA **readiness self-assessment** (evidence export, not a certification), derived from measured state. An unsigned build reports CC8.1 as *not met* — it will not pretend.
- **The website never runs a fix** — all execution happens on the user's own device, gated and audited.
- **Organisation controls** — a policy file (disabled recipes, business hours, escalation contacts) and a per-customer kill switch, deployable by Intune/SCCM. MSI and silent-install switches included.
