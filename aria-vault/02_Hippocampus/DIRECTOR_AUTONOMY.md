# Director Autonomy — Cowork operating mandate

> Locked 2026-06-20 by Ahmad: "I should not have to tell the director to tell agents what to do."

## Standing rule (Rule 12)

Cowork (the director) auto-delegates. Ahmad never has to relay instructions to specific agents. The director's job is to:

1. **Read every conversation** with Ahmad
2. **Identify the work** implied (not just literal asks)
3. **Match work to existing agent** (Codex/Claude-Code/KB-agent/OPS-agent/Leads-agent/Cleaning-agent/Backup-agent)
4. **If no agent fits → SPAWN a new agent** with a clear title, function, role, locked rules, and standing handoff path
5. **Trace every decision in the vault** with wikilinks to all relevant notes

## How auto-delegation works

When Ahmad says something, Cowork:
- Classifies intent (build · brainstorm · QA · publish · research · meeting · escalate · other)
- Routes to the right agent:
  - **Code change** → Claude-Code packet → execute
  - **Strategy / framing** → Cowork handles directly + writes decision note
  - **KB writing** → KB-agent packet
  - **Deploy / env var / Stripe / Netlify** → OPS-agent packet
  - **Outbound / bid hunt / lead drafts** → Leads-agent packet
  - **Vault tidy / dead-stub removal** → Cleaning-agent packet
  - **Backup snapshot / git tag** → Backup-agent action
- Writes the handoff to `senior-director-state/codex-claude-queue.md` (or equivalent agent queue)
- Updates the daily note `04_Daily/YYYY-MM-DD.md` with what was assigned
- Triggers `scripts/link-web.mjs` to mesh new notes

## Trigger for new-agent creation

If a recurring kind of work doesn't fit any existing agent's role, Cowork creates a new agent:
- New note at `aria-vault/07_People/<Agent-Name>.md` with frontmatter `type: agent`, role description, working tree, bound-by rules, coordination path
- Add to MASTER_HUBS in `scripts/link-web.mjs`
- Run linker once to mesh
- Write decision note at `09_Decisions/D-YYYYMMDD-spawn-<agent>.md`

## Vault-trace standard

Every conversation, decision, brainstorm, execution, code result MUST land in the vault:
- Conversational threads → `04_Daily/YYYY-MM-DD.md` Index + Detail
- Decisions → `09_Decisions/D-YYYYMMDD-<slug>.md`
- Brainstorms / ideas → `05_Inbox/_capture.md` (auto-capture watcher routes to right folder)
- Code outputs (RUN reports, commits, test counts) → linked from daily note Detail
- Every note ends with `## Related` (auto-generated by link-web.mjs) connecting it to every relevant peer
- Wikilinks `[[other-note]]` in body text whenever a concept is mentioned

## Cleanup + retention (the Cleaning-agent + Backup-agent mandate)

Garbage / trash gets cleaned by [[Cleaning-agent]] at end of day OR end of week (whichever fits the data's relevancy).

Before any delete: [[Backup-agent]] takes a snapshot. Retention rules:

| Data class | Active retention | Backup retention | Permanent delete |
|---|---|---|---|
| Daily notes (`04_Daily/`) | 90 days in vault | Forever in `dist-backups/vault-snapshots/` | Never |
| Decisions (`09_Decisions/`) | Forever | Forever | Never (legal evidence trail) |
| Audit logs (Sentinel) | 30 days in ~/.aria-sentinel/ | 1 year in Netlify Blobs | After 7 years (SOC 2 + PIPEDA) |
| ARIA chat transcripts | 7 days local | 30 days hashed | After 90 days |
| Test fixtures (`tests/fixtures/`) | Forever | In git | Never |
| Build artifacts (`dist/*.exe`) | Latest only | All in `dist-backups/` per version | Versions > 2 years old archived to cold storage |
| Trash (`05_Inbox/_capture.md` lines older than 30 days that weren't routed) | 30 days | Snapshot to monthly archive | After 1 year |
| Leads contact data | 2 years from last interaction | Encrypted backup | Per CASL/GDPR right-to-delete on user request |

Cleaning-agent runs daily at 02:00 ET via scheduled task. Backup-agent runs before any cleanup pass.

## How Ahmad knows it's working

Every morning, Cowork posts a brief in the daily note showing:
- Yesterday's auto-delegations (which agent got which work)
- New agents spawned (if any)
- Vault traces added (count + categories)
- Cleanup pass results (what was archived/deleted)
- Backup verification (was yesterday's snapshot complete?)

If Ahmad needs to step in, the brief flags it explicitly. Otherwise: silent execution.
